# BarReplay Yearly Tick Merger

پروژهٔ مستقل برای ادغام BINهای روزانهٔ موجود در دیتاست عمومی Esmaeil9ss/Tickdata در Hugging Face، ساخت SYMBOL_YEAR.BIN و ZIP آن و انتشار در GitHub Releases همین مخزن. پروژهٔ قبلی تغییر نمی‌کند.

## اجرای اولیه

با اولین آپلود workflow در شاخهٔ main، **EURUSD سال ۲۰۲۶ خودکار اجرا می‌شود**. این اجرا با تگ `yearly-eurusd-2026` منتشر می‌شود. تغییر بعدی خود فایل workflow نیز اجرای پیش‌فرض را آغاز می‌کند؛ تغییر فایل‌های دیگر به‌تنهایی اجرای ادغام را آغاز نمی‌کند.

## اجرای دستی برای نماد یا سال دیگر

Actions → Merge yearly tick data and publish Release → Run workflow

| ورودی | نمونه |
| --- | --- |
| symbol | EURUSD یا USDJPY |
| year | 2026 |
| release_tag | yearly-eurusd-2026-v2 |
| overwrite | پیش‌فرض خاموش؛ فقط برای جایگزینی عمدی خروجی قبلی روشن کنید |

نام پوشهٔ نماد در منبع باید با نماد ورودی سازگار باشد. برنامه از شاخهٔ اصلی دیتاست یک commit ثابت انتخاب می‌کند و تمام دانلودها را از همان snapshot انجام می‌دهد؛ تغییر هم‌زمان منبع، فایل‌های یک اجرا را مخلوط نمی‌کند.

## مسیر منبع و پوشش

مثال مسیرهای استفاده‌شده:

```
EURUSD/EURUSD_2026-01-01.BIN
EURUSD/EURUSD_2026-01-02.BIN
...
```

فهرست از API رسمی Hugging Face با تمام صفحات آن خوانده می‌شود؛ فقط فایل‌های روزانه با نام دقیق نماد و سال انتخاب می‌شوند. فایل‌های پوشهٔ `ranges`، آرشیوهای سالانه، فایل‌های news در `daily` و سایر شکل‌های نام به عمد وارد ادغام نمی‌شوند. این برنامه به index.txt به‌عنوان فهرست کامل متکی نیست.

فقط داده‌های واقعاً موجود در این پوشهٔ استاندارد ادغام می‌شوند؛ خروجی ۲۰۲۶ لزوماً کل سال ۲۰۲۶ نیست. تاریخ اولین و آخرین تیک، روزهای دارای منبع و روزهای بدون فایل منبع در گزارش ثبت می‌شوند. نبود فایل روزانه الزاماً به معنی نقص داده نیست؛ تعطیلی بازار یا آینده‌بودن روز هم ممکن است علت باشد. برنامه دادهٔ مفقود را حدس نمی‌زند یا تولید نمی‌کند.

## خروجی Release

```
EURUSD_2026.zip
  EURUSD_2026.BIN
EURUSD_2026_report.json
EURUSD_2026_SHA256SUMS.txt
```

فقط BIN داخل ZIP است؛ گزارش و هش‌ها asset جدا هستند. BIN خام در فضای موقت اجرا نیز ساخته می‌شود ولی برای جلوگیری از آپلود تکراری و حجیم فقط ZIP در Release قرار می‌گیرد. ZIP برای اکسپرت باید ابتدا استخراج شود. خصوصی یا عمومی بودن دانلودها به وضعیت مخزن بستگی دارد؛ این مخزن ابتدا Private ساخته شده است.

ریلیز تازه ابتدا Draft ساخته می‌شود؛ پس از آپلود موفق فایل‌ها منتشر می‌شود. ریلیز موجود با تنظیمات Draft/Prerelease خودکار تغییر وضعیت نمی‌دهد. overwrite خاموش، از جایگزینی خروجی نماد/سال قبلی جلوگیری می‌کند. برای نگه‌داشتن snapshot قدیمی تگ جدید انتخاب کنید. انتشار چند asset اتمیک نیست؛ در خطای شبکه، ریلیز ممکن است ناقص باقی بماند و باید بررسی شود.

## سازگاری با BarReplay bin_v1

هر بلوک:

1. تعداد تیک: int32 little-endian
2. تمام زمان‌ها: int64 little-endian، میلی‌ثانیه UTC از Unix epoch
3. تمام Bidها: float64 little-endian
4. تمام Askها: float64 little-endian

بلوک‌ها بدون افزودن هدر یا تغییر قیمت/زمان و بر اساس ترتیب زمانی کپی می‌شوند. خواندن تمام زمان‌ها و قیمت‌ها، شمارش تیک، محدودیت بلوک، مرتب‌بودن زمان‌ها، تطبیق روز فایل و ساعت UTC بررسی می‌شود. بعد از ادغام فایل سالانه دوباره مستقل بررسی می‌شود.

هر بلوک باید داخل یک ساعت UTC باشد. برای سازگاری با بخش compaction اکسپرت، بلوک ساعتی تکراری ولی متفاوت باعث توقف است، نه حذف یا بازنویسی داده. فقط یک بلوک کامل کاملاً یکسان، با SHA-256 یکسان، قابل ردکردن به‌عنوان تکرار است. تیک‌های منفرد با زمان یکسان حذف نمی‌شوند. ورودی نامرتب خودکار مرتب یا اصلاح نمی‌شود؛ خطا گزارش می‌شود.

حجم معامله در قالب فعلی وجود ندارد. قیمت‌ها گرد نمی‌شوند و قیمت منفی متناهی نیز معتبر است. NaN/Infinity و دادهٔ ناقص رد می‌شود.

## بررسی سلامت و محدودیت‌ها

- دانلود عمومی است؛ توکن Hugging Face لازم نیست. منبع خصوصی در این نسخه پشتیبانی نمی‌شود.
- منبع در یک commit ثابت قفل می‌شود و اندازهٔ هر دانلود با فهرست تطبیق داده می‌شود. اگر API هش LFS بدهد، SHA-256 آن نیز بررسی می‌شود.
- ساخت BIN و ZIP جریانی است؛ کل سال در RAM قرار نمی‌گیرد. هر بار فقط یک فایل روزانه روی دیسک دانلود می‌شود.
- ZIP نهایی مجدداً خوانده و SHA-256 بایت‌های BIN داخل آن با BIN ساخته‌شده مقایسه می‌شود. گزارش، هش همهٔ ورودی‌ها و خروجی‌ها را دارد.
- هر ZIP ریلیز باید کمتر از ۲ GiB باشد. بزرگ‌تر باشد، برنامه متوقف می‌شود و بدون اجازه فایل را قطعه‌قطعه نمی‌کند.
- فایل روزانه حداکثر ۴ GiB؛ تعداد تیک هر بلوک حداکثر ۲۰ میلیون. فضای آزاد قبل از شروع برای BIN، ZIP و حاشیهٔ امن بررسی می‌شود.
- سقف زمان اجرای GitHub Actions در این پروژه ۱۲۰ دقیقه است. سهمیه یا هزینهٔ Actions، محدودیت شبکه و فضای Runner به حساب و محیط بستگی دارد.
- از GITHUB_TOKEN موقت همان مخزن برای انتشار استفاده می‌شود؛ رمز یا PAT در کد ذخیره نشده و به Hugging Face ارسال نمی‌شود.
- فایل run-status.json پس از هر اجرا در مخزن ثبت می‌شود؛ شامل لینک اجرا، وضعیت و در صورت ساخت خروجی، شمارش و هش‌هاست. این commit اجرای ادغام دیگری را آغاز نمی‌کند.

## اجرای محلی و تست

Python 3.10+ بدون وابستگی اضافی:

```
python -m unittest discover -s tests -v
python scripts/merge_year.py --symbol EURUSD --year 2026 --output output
```

پوشهٔ خروجی نباید از قبل وجود داشته باشد. محلی فقط ادغام و ZIP انجام می‌شود؛ انتشار توسط مرحلهٔ جداگانهٔ GitHub انجام می‌شود.

۱۴ تست آفلاین شامل ادغام، حفظ بایت‌ها و تیک هم‌زمان، رد بلوک خراب/هم‌پوشان، ZIP و گزارش موفق بودند. یک فایل واقعی EURUSD مربوط به ۲۰۲۶-۰۱-۰۲ هم بررسی شد: ۲۲ بلوک ساعتی و ۵۱۹۰۶ تیک. این بررسی جایگزین آزمایش نهایی خروجی در MT5 نیست.
